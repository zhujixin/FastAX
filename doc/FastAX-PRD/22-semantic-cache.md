### 6.18 语义缓存引擎（CACHE）

参考 PromptCache、Cloudflare AI Gateway、Bifrost、SnackCache 等行业方案。语义缓存是 AI 网关降低成本和延迟的核心能力，行业标杆命中率 50-70%，可节省 30-80% API 调用成本。

**架构模式：双层缓存流水线**

```
客户端请求 → 精确匹配哈希 (SHA256, Redis, <1ms) → 命中? 
              ↓ MISS
            向量相似度搜索 (384维, 5-10ms) → 高相似度(≥0.90)? 
              ↓ 灰色区(0.80-0.90)
            廉价模型验证 (gpt-4o-mini, 5-10ms) → 同义? 
              ↓ 确认不同
            调用源 LLM → 返回 + 写入缓存
```

| 功能 | 需求描述 | 优先级 | 备注 |
|------|----------|--------|------|
| CACHE-01 | **精确匹配缓存**：对请求体计算 SHA256 哈希，Redis 中精确匹配命中则直接返回缓存响应，延迟 ≤ 1ms | P0 | 最简单、零风险的第一层缓存，预计命中 15-25% |
| CACHE-02 | **语义向量缓存**：将请求文本向量化（384维，推荐 all-MiniLM-L6-v2 本地运行），在向量数据库中检索余弦相似度 ≥ 阈值的缓存条目，命中返回 | P1 | 阈值 0.90-0.95（FAQ）/ 0.85-0.90（对话）；参考 PromptCache 向量检索方案 |
| CACHE-03 | **灰度区 LLM 验证**：当余弦相似度落在 0.80-0.90 区间时，使用廉价模型（如 gpt-4o-mini）判断是否与原请求同义，确认同义则返回缓存，否则调用源 LLM | P2 | 防止语义缓存误命中；参考 PromptCache 灰度区方案 |
| CACHE-04 | **缓存控制头**：支持通过 HTTP Header 按请求控制缓存行为 —— `x-fastax-cache-ttl`（自定义 TTL）、`x-fastax-cache-skip`（跳过缓存）、`x-fastax-cache-key`（自定义缓存键） | P0 | 参考 Cloudflare AI Gateway `cf-aig-*` 风格控制头 |
| CACHE-05 | **流式 SSE 响应缓存**：缓存 SSE 流式响应，命中时从缓存中逐块回放，支持中断恢复 | P2 | 技术难点：流式响应可能不完整、中途断开 |
| CACHE-06 | **缓存计费**：缓存命中的请求按原价百分比计费（默认 10-30%），管理员可按模型/用户维度配置折扣比率 | P1 | 与 COST-03 联动，缓存命中降低用户费用 |
| CACHE-07 | **缓存命名空间隔离**：按用户 ID 或团队 ID 做命名空间隔离（Redis 前缀或向量索引分区），防止跨用户缓存污染导致信息泄露 | P1 | 安全关键：必须确保用户 A 的缓存不会返回给用户 B |

**关键设计决策**：

| 决策 | 要点 | 参考 |
|------|------|------|
| **缓存存储后端** | Redis（精确匹配 + 元数据）+ 本地向量索引（语义匹配），可选 Milvus/Weaviate 做大容量扩展 | PromptCache BadgerDB + ANN; Bifrost Weaviate |
| **向量化模型** | all-MiniLM-L6-v2（~23MB, 384维），本地 CPU 推理，零延迟零费用 | SnackCache FAISS + SentenceTransformer |
| **TTL 策略** | 默认 1h（通用），FAQ 类可设 24h，流式 30min；支持按模型/供应商自定义 | — |
| **缓存驱逐** | LRU + TTL 双重驱逐；精确缓存内存上限 1GB，语义缓存向量数上限 100 万 | — |
| **一致性** | 缓存失效通过 Redis Pub/Sub 广播到多实例；供应商模型升级时批量清除相关缓存 | — |
| **监控** | 缓存命中率、缓存延迟、缓存节省金额仪表板（与 OBSV-06 联动） | — |

**实施路径**：

| 阶段 | 内容 | 预计人日 |
|------|------|---------|
| Phase 1 | 精确匹配缓存（CACHE-01 + CACHE-04 + CACHE-06） | 3-5d |
| Phase 2 | 语义向量缓存（CACHE-02 + CACHE-07） | 5-8d |
| Phase 3 | 灰度区验证 + 流式缓存（CACHE-03 + CACHE-05） | 5-8d |
